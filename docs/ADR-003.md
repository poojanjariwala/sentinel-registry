# ADR-003: Department-scoped RBAC enforced in the query layer

**Status:** Accepted · **Date:** 2026-09-25

## Context
The problem statement requires "department-wise role-based access control."
Checking permissions only at route level still leaks cross-department data through
filters, exports, GIS queries and bulk-import targets.

## Decision
- Roles: `STATE_ADMIN`, `DEPARTMENT_ADMIN`, `OPERATOR`, `AUDITOR`, `VIEWER`.
- Effective permissions = role defaults + per-user grants/denials (`permissions` table).
- Department scope derives from `user_roles.department_id`; `STATE_ADMIN`/`AUDITOR`
  are unrestricted.
- Every camera query path (list, GIS, export, detail, gap analysis, import target
  validation) applies the same scope predicate from one shared helper
  (`camera_service.user_department_filter`).

## Rationale
- One predicate, tested once, applied everywhere — no endpoint-by-endpoint drift.
- Import-time scope checks prevent a department operator from creating/updating rows
  that belong to another department, even via CSV.

## Consequences
- Users with a role but no department scope see nothing (safe default).
- Cross-department reads need explicit grants (`permissions` table), not code changes.
