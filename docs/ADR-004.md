# ADR-004: Bulk import — dry-run first, idempotent upsert on camera_code

**Status:** Accepted · **Date:** 2026-09-25

## Context
Departments will onboard hundreds of cameras via CSV/XLSX. Bad rows must never
partially commit, and repeated uploads (corrected files, refreshed extracts) must be safe.

## Decision
- `POST /cameras/import?dry_run=true|false` (multipart file, CSV or XLSX, ≤5000 rows).
- Every row is validated (required fields, enum domains, Gujarat bounding box,
  date formats, department resolution, operator scope, in-file duplicate codes).
- Errors are reported per row (`row number + reasons`) and those rows are skipped;
  valid rows are upserted keyed on `camera_code` (update if exists, insert otherwise).
- Each run is stored as a `camera_import_batches` record with counts + report,
  and audited as `CAMERA_IMPORT`.

## Rationale
- Government data arrives messy; a blocking all-or-nothing import forces dozens of
  round trips. Row-level skip-with-report lets operators fix and re-upload quickly.
- Idempotent upsert makes the "corrected file" workflow safe by construction —
  demonstrated in the demo by committing the same file twice.

## Consequences
- Duplicate `camera_code` inside one file is an error (ambiguous intent), while a
  duplicate against the database is an update (idempotent re-upload).
- The UI disables **Commit** until a dry run reports zero errors.
