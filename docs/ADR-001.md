# ADR-001: Backend stack — Python FastAPI + PostgreSQL/PostGIS

**Status:** Accepted · **Date:** 2026-09-25

## Context
Module 1 needs a registry API with GIS geometry, bulk import, RBAC and audit.
The problem statement allows Node.js or Python (Django/FastAPI) and mandates
PostgreSQL + PostGIS. The hackathon's recommended stack lists Python and FastAPI.

## Decision
Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic + Pydantic v2, on PostgreSQL 16
with PostGIS 3.4 (Docker image `postgis/postgis:16-3.4`).

## Rationale
- Auto OpenAPI 3 documentation satisfies the "Registry API documentation" deliverable for free.
- SQLAlchemy 2 + GeoAlchemy2 give first-class PostGIS geometry with portable ORM code.
- Alembic gives versioned, reviewable schema migrations (acceptance AC-1).
- One language across the future AI modules (Modules 3+: ANPR runs in Python ecosystems).

## Consequences
- Team should prefer small service modules over one large module (per Backend Schema doc §51).
- Later models (Module 2+ viewing, Module 3 AI) can reuse the same auth/session contract.
