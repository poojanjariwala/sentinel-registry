# ADR-006: Selective analytics — simulated ANPR engine behind a swappable contract

**Status:** Accepted · **Date:** 2026-09-25

## Context
Module 2 calls for ANPR-based metadata generation, event tagging, camera-wise
indexing, searchable vehicle-movement records and watchlist alerts. Real
inference (YOLO + plate OCR) needs GPU hardware and calibrated models that a
browser-only demo environment cannot guarantee.

## Decision
- `tick_simulated_anpr` (a background loop, 8 s cadence) generates realistic
  observations on streams where `analytics_enabled = true`: state-format plates,
  classes, speeds, confidences. ~12 % of plates are drawn from the watchlist so
  the alert path always has demo traffic.
- Every observation stores `engine='simulated'` so simulated data is
  distinguishable from real inference output — production would replace the
  worker with a model-backed implementation writing the identical
  `vehicle_observations` rows (`engine='yolo-v8-anpr'`, model version in meta).
- Watchlist hits raise at most one alert per plate per 10 minutes (dedupe) with
  severity inherited from the watchlist entry; all lifecycle actions are audited.
- Vehicle search normalizes plates (`GJ-01 AB 1O34 → GJ01AB1034`, O→0) and falls
  back to last-4 partial matching when exact search finds nothing.

## Rationale
- The ANPR value chain (observation → tag → watchlist match → alert → ack/close)
  is the deliverable; the perception engine behind it is replaceable. Keeping the
  contract stable lets a real model be integrated without touching API or UI.
- Honest provenance (`engine` column, UI badges) aligns with the challenge's
  no-fake-data posture: simulated feeds are labelled as such everywhere.

## Consequences
- Observations table grows continuously; a retention job (older than N days)
  should be added before long-running demos. Volume at 8 s cadence × ~20 streams
  is modest (~30 k rows/hour worst case at full analytics coverage).
- Integrating real ANPR later: deploy GPU worker, set `analytics_enabled`
  per stream, write rows with real confidences — no schema change needed.
