# ADR-002: Gap analysis — H3 hexagonal grid

**Status:** Accepted · **Date:** 2026-09-25

## Context
"Gap-analysis reports for uncovered zones" needs a concrete geographic unit.
Options: administrative boundaries (village/taluka), square grid, hex grid,
camera coverage-radius buffers.

## Decision
Uber H3 hexagons at configurable resolution (default 8, roughly 460 m edge-to-edge),
each cell classified by camera count (COVERED / THIN at a configurable threshold).
Ageing infrastructure and AMC expiry are computed per camera and pivoted per district.

## Rationale
- Hexagons have uniform neighbour distance — good for coverage adjacency analysis later.
- Resolution is a runtime parameter, so the same engine serves city-level (res 9)
  and district-level (res 7) reviews without schema changes.
- Administrative units remain in the report as the district pivot table, keeping the
  output readable for government stakeholders.

## Consequences
- The `h3` Python package becomes a runtime dependency (~small, pure wheels available).
- "Uncovered zone" here means *no camera in cell* — a planning signal, not a guarantee
  of surveillance gap (a neighbouring cell's PTZ may still cover the area). This is
  stated in the UI to avoid overclaiming.
